## Business rules

1. Scope every nested id to its restaurant and vendor before joining; caller-supplied owner IDs never create authorization. Public discovery returns active visible entities and excludes private business, wallet and device-token fields.
2. Catalog mutation validates variation/addon/option cardinality and ownership; price conversion uses configured exponent and bigint. Deleted/out-of-stock options cannot be ordered; historical order snapshots remain readable.
3. Keep original misspellings updateRestaurantBussinessDetails and bussinessDetails and upstream \_\_typename values Food, RestaurantPreview, RestaurantCarouselPreview, RestaurantDetail. Retain GeoJSON order and array opening-time format.
4. Discovery applies geospatial delivery eligibility, shop/cuisine filters, open/available status, bounded pagination and deterministic tie-breaking. Recent-order discovery requires caller identity; aggregate popularity uses actual eligible orders rather than fabricated ranking.
5. DuplicateRestaurant clones catalog with fresh IDs and remapped internal links atomically; does not clone credentials, sessions, payouts, reviews or orders. Concurrent duplicate and edits cannot create mixed snapshots.
6. Soft deletes retain immutable order/ledger history. hardDeleteRestaurant cannot erase financial/order evidence; refuse with CONFLICT where dependencies exist. Enforce active-reference constraints on vendor/category/addon deletion.
7. Coupon reads never imply validity at checkout: L5 recomputes eligibility and reserves usage atomically. Restrict coupon mutations to correct admin permission/restaurant ownership; validate expiration boundaries and cap discounts. Reviews read real delivered-order reviews written by L5; timestamps are epoch-millisecond strings.

Client auth errors preserve `UNAUTHENTICATED`, `TOKEN_EXPIRED`, `INVALID_TOKEN`, `FORBIDDEN`; use the master error table. Invalid business inputs use `BAD_USER_INPUT`; missing/unseen entities use `NOT_FOUND`; concurrent state/version conflicts use `CONFLICT`. Unimplemented capability returns `NOT_IMPLEMENTED`. Unconfigured provider returns `PROVIDER_UNAVAILABLE`; unavailable infrastructure must fail visibly. Business error messages must avoid token-retry trigger phrases. Any inferred policy not established in references must be recorded as UNVERIFIED and independently reviewed before release.

Each task below is independently tracked. Shared code may be factored, but every root needs its own assertion set and resolver mapping. Public roots instead prove intentional public access plus safe field projection, missing public handshake denial, abuse limits and malformed inputs. Scalar/no-ID roots record why ownership substitution is inapplicable and test recipient/session binding instead. Read tasks run pagination/filter isolation, inactive/deleted visibility and concurrent update/read consistency.
