## Business rules

1. configuration/publicConfiguration project an explicit public allowlist; privileged fields are null for public/customer/rider callers. Never expose Stripe, PayPal, Twilio, email, Firebase or object-store secrets.
2. Configuration saves validate all selected fields, persist revision and audit in one transaction, activate atomically and invalidate caches after commit; competing revisions return CONFLICT. Retain last valid activation on failed validation.
3. Currency exponent and delivery/tax/tip rates are server-owned; store bigint minor amounts or bounded rational rates, never floating point arithmetic. Configuration change never reprices existing orders.
4. Zones require closed, non-self-intersecting polygons and [longitude,latitude] coordinates; update/delete cannot orphan restaurant/rider assignments. Validate bounds and pagination using kernel helpers.
5. uploadToken/uploadImageToS3 enforce authenticated ownership, MIME/size/expiry restrictions, generated object keys and private storage; reject traversal, executables, stale tokens and unrelated asset references. Unconfigured object store returns PROVIDER_UNAVAILABLE.
6. REST maps proxy validates bounded coordinates/query length and language, rate limits requests and keeps Google credentials server-side. No hard-coded production fallback. Countries/cities use a versioned dataset with recorded source; unknown ISO fails validation.

Client auth errors preserve `UNAUTHENTICATED`, `TOKEN_EXPIRED`, `INVALID_TOKEN`, `FORBIDDEN`; use the master error table. Invalid business inputs use `BAD_USER_INPUT`; missing/unseen entities use `NOT_FOUND`; concurrent state/version conflicts use `CONFLICT`. Unimplemented capability returns `NOT_IMPLEMENTED`. Unconfigured provider returns `PROVIDER_UNAVAILABLE`; unavailable infrastructure must fail visibly. Business error messages must avoid token-retry trigger phrases. Any inferred policy not established in references must be recorded as UNVERIFIED and independently reviewed before release.
